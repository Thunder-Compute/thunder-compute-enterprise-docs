KubeVirt VMs receive Thunder GPUs the same way pods do, through Dynamic Resource
Allocation. Two differences: a VM needs a **stable claim name** so it can mount the
guest artifacts Thunder generates for it, and KubeVirt needs its own feature gate
before it will accept DRA-backed GPUs at all.

<Note>
  This page assumes a working Thunder installation on the cluster. Complete
  [Kubernetes](/kubernetes) first: the feature gate, node labels, and chart deployment
  are shared, and are not repeated here.
</Note>

## Enable GPUsWithDRA

KubeVirt VMs receive GPUs through `ResourceClaims`, a DRA construct, which requires
the `GPUsWithDRA` feature gate. This feature may be gated in default KubeVirt charts.

Enable it without removing any existing KubeVirt feature gates:

```bash
feature_gates="$(kubectl -n kubevirt get kubevirt kubevirt -o json \
  | jq -c '(.spec.configuration.developerConfiguration.featureGates // []) as $gates | if $gates | index("GPUsWithDRA") then $gates else $gates + ["GPUsWithDRA"] end')"

kubectl -n kubevirt patch kubevirt kubevirt \
  --type merge \
  -p "{\"spec\":{\"configuration\":{\"developerConfiguration\":{\"featureGates\":${feature_gates}}}}}"
```

Verify the feature gate:

```bash
kubectl -n kubevirt get kubevirt kubevirt \
  -o jsonpath='{.spec.configuration.developerConfiguration.featureGates}{"\n"}'
```

Expected output includes:

```text
["GPUsWithDRA"]
```

## Requesting GPUs from a VM

VMs use a stable `ResourceClaim`, not a `ResourceClaimTemplate`, because the claim
name determines the guest artifacts the daemon creates:

```text
<claim-name>-thunder-configmap   # install-thunder-client.sh
<claim-name>-thunder-secret      # enrollment-token
```

<Note>
  A VM claim cannot use the `resources.limits` form: the artifact names come from the
  claim name, so the claim has to exist before the VM does.
</Note>

Create the VM claim. `count` is the number of GPUs, and the selector pins the model
(see [Pinning a GPU type](/kubernetes#pinning-a-gpu-type)):

```yaml
apiVersion: resource.k8s.io/v1
kind: ResourceClaim
metadata:
  name: thunder-vm-claim
spec:
  devices:
    requests:
      - name: gpu
        exactly:
          deviceClassName: thunder-gpu
          allocationMode: ExactCount
          count: 1                      # one device per GPU
          selectors:
            - cel:
                expression: device.attributes["thundercompute.com"]["gpu_type"] == "A6000"
```

Reference the claim from the VM and mount the Thunder guest artifacts with
virtiofs:

```yaml
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: thunder-vm
spec:
  running: true
  template:
    spec:
      resourceClaims:
        - name: gpu
          resourceClaimName: thunder-vm-claim
      domain:
        resources:
          requests:
            memory: 1Gi
        devices:
          filesystems:
            - name: thunder-config
              virtiofs: {}
            - name: thunder-secret
              virtiofs: {}
          disks:
            - name: cloudinitdisk
              disk:
                bus: virtio
      volumes:
        - name: thunder-config
          configMap:
            name: thunder-vm-claim-thunder-configmap
            optional: true
        - name: thunder-secret
          secret:
            secretName: thunder-vm-claim-thunder-secret
            optional: true
        - name: cloudinitdisk
          cloudInitNoCloud:
            userData: |
              #cloud-config
              mounts:
                - [ thunder-config, /mnt/thunder-config, virtiofs ]
                - [ thunder-secret, /mnt/thunder-secret, virtiofs ]
              runcmd:
                - [ bash, /mnt/thunder-config/install-thunder-client.sh ]
```

Use the test chart for a complete VM with root disk and networking:

```bash
helm install thunder-vm charts/tests/vm \
  --set gpu.type=A6000 \
  --set gpu.count=1
```

Inspect the VM and its generated Thunder artifacts:

```bash
kubectl get vm,vmi,pod -l app.kubernetes.io/instance=thunder-vm
kubectl get resourceclaim thunder-vm-thunder-gpu-test-vm-claim -o yaml
kubectl get cm,secret | grep thunder-vm-thunder-gpu-test-vm-claim
```
